## What it is

JobPilot is a fully **static, browser-only** job-search and resume-tailoring app. There is no backend server, no database, and no Python at runtime. The site is generated from Jinja-shaped templates into plain HTML/JS/CSS and served from GitHub Pages. A thin Cloudflare Worker exists only to proxy CORS-blocked job-board API calls — it stores nothing, logs no request bodies, and never sees your API keys at rest.

Everything you create — resumes, BYOK API keys, search history — lives in your browser (Google Drive `appDataFolder` for resumes, `localStorage` AES-GCM vault for keys).

**Component map** (everything in this repo):

| Path | Purpose |
|---|---|
| [jobpilot/templates/](jobpilot/templates) | Jinja-shaped source templates (`base.html`, `landing.html`, `index.html`) |
| [jobpilot/static/](jobpilot/static) | Source CSS and JS (mirrored into `docs/static/` at build) |
| [scripts/build_pages.py](scripts/build_pages.py) | Stdlib-only static-site builder: strips Jinja syntax + substitutes `{{ google_client_id }}` from env, emits `docs/` |
| `docs/` | Built artifact, deployed to GitHub Pages (git-ignored — regenerated by CI) |
| [proxy/worker.js](proxy/worker.js) | Cloudflare Worker: stateless POST `/search` forwarder |
| [proxy/wrangler.toml](proxy/wrangler.toml) | Worker config + `ALLOW_ORIGINS` |
| [.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml) | CI: rebuild + publish to GitHub Pages on every push to `master` |

**Auth**: Google Identity Services only. Sign-in returns an ID token that's parsed client-side for `email` / `name` / `picture` and an access token scoped to `drive.appdata` + `drive.file` so resumes can be synced to your Drive immediately. There is no server-side session, no signing secret, no cookie.

## Local development

The build is pure-Python stdlib — no `pip install` needed.

```pwsh
# 1. Clone
git clone https://github.com/<your-fork>/jobpilot.git
cd jobpilot

# 2. Build the static site into docs/
#    (Optional: set GOOGLE_CLIENT_ID to enable the Google Sign-In button.
#     Without it, only the Demo path is reachable.)
$env:GOOGLE_CLIENT_ID = "<your-client-id>.apps.googleusercontent.com"
python scripts/build_pages.py

# 3. Open in a browser
start docs/index.html      # Windows
# open docs/index.html     # macOS
# xdg-open docs/index.html # Linux
```

For a local web server (recommended — `file://` blocks some browser features):

```pwsh
python -m http.server 8000 --directory docs
# then open http://localhost:8000/
```

To iterate, edit anything under [jobpilot/templates/](jobpilot/templates) or [jobpilot/static/](jobpilot/static) and rerun `python scripts/build_pages.py`. The script is fast (<1 s) and idempotent.

## Cloudflare Worker setup

The Worker is what makes the job-board APIs reachable from the browser (most of them block direct browser calls via CORS). See [proxy/README.md](proxy/README.md) for the full setup; the short version is:

```pwsh
npm install -g wrangler
wrangler login
cd proxy
wrangler deploy
```

Copy the printed `https://jobpilot-proxy.<your-subdomain>.workers.dev` URL into JobPilot's **Settings → Job search → Cloudflare Worker URL** field. The URL is persisted in your in-browser BYOK vault as `cf_worker_url`.

Before going to production, tighten [proxy/wrangler.toml](proxy/wrangler.toml)'s `ALLOW_ORIGINS` to your own domain.

## Configuration

The only configurable value is `GOOGLE_CLIENT_ID`, and it is baked into `docs/` at build time (substituted by [scripts/build_pages.py](scripts/build_pages.py) into the landing page's GSI button). For GitHub Pages deploys it comes from a repository secret of the same name — see [.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml).

### Enable Google Sign-In

1. Open the [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials).
2. Create an **OAuth 2.0 Client ID** of type *Web application*.
3. Add **Authorized JavaScript origins** for every domain you serve from, e.g. `https://www.jobspilot.site` and `http://localhost:8000`.
4. On the **OAuth consent screen** add the scopes:
   - `openid`, `email`, `profile`
   - `https://www.googleapis.com/auth/drive.appdata`
   - `https://www.googleapis.com/auth/drive.file`
5. Add the Client ID to your environment:
   - **Local:** `$env:GOOGLE_CLIENT_ID = "..."` before running `python scripts/build_pages.py`.
   - **GitHub Pages:** add a repository secret named `GOOGLE_CLIENT_ID`. The deploy workflow reads it.
6. Rebuild and reload. Append `?debug=1` to the landing URL to render a "not configured" hint when the variable is missing — useful when triaging a deploy.

Demo mode requires no configuration and works without `GOOGLE_CLIENT_ID`.

## BYOK keys

Every provider that needs an API key uses **BYOK** (Bring-Your-Own-Key). Keys are stored as an AES-GCM blob in `localStorage` (key `jp_byok_v1`); the symmetric key is derived from your signed-in Google email + a passphrase via PBKDF2-SHA-256 (200 000 iterations) and lives only in tab memory once unlocked. Nothing leaves your browser except the outbound API call.

Where to add keys: **Settings → AI** and **Settings → Job search** in-app.

| Provider | Header sent | Used for |
|---|---|---|
| Anthropic | `X-Anthropic-Key` (+ optional `X-Claude-Model`) | All AI features (ATS scoring, tailoring, chat-style edits, generation) |
| JSearch (RapidAPI) | `X-RapidAPI-Key` | Aggregated LinkedIn / Indeed / Glassdoor / ZipRecruiter results |
| Adzuna | `X-Adzuna-App-Id` + `X-Adzuna-App-Key` | Adzuna job search |
| USAJobs | `X-USAJobs-Email` + `X-USAJobs-Key` | US Federal jobs |

The Muse, Remotive, and Arbeitnow need no key.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Landing page shows only "Try Demo" — no Google button | `GOOGLE_CLIENT_ID` was empty at build time | Rebuild with the secret set; for CI ensure the repo secret exists |
| "Cloudflare Worker URL not set" toast on job search | No `cf_worker_url` in BYOK vault | Deploy the Worker (see above), paste its URL into **Settings → Job search** |
| AI buttons surface "AI requires an Anthropic API key" | No `X-Anthropic-Key` in BYOK vault | Add your key in **Settings → AI** |
| Job search returns nothing for a US city | The provider returned non-US results that were filtered out | Try `United States` as the location, or broaden the title |
| PDF/DOCX export looks different from the in-app preview | Browser-side rendering uses jsPDF / docx.js — there is no server WeasyPrint path on the static deploy | Expected — visual drift vs. legacy server renders is accepted |
